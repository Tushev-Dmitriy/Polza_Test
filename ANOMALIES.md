# Аномалии входных данных

Проверка выполнена скриптом импорта и дополнительным сравнением `review.csv` со
всеми 20 JSON-страницами. Номера строк CSV ниже включают строку заголовка.

## Краткий итог

`review.csv` содержит 207 строк данных. Из них 178 добавляют новые компании,
6 обновляют уже известные записи, 9 являются дублями и 14 отклоняются из-за
некорректных данных. Некоторые отклонённые строки имеют более одной проблему.

## 1. CSV не является только «свежей выгрузкой»

Шесть записей уже есть в JSON с теми же ID и теми же значениями:

`c_000263`, `c_000851`, `c_000098`, `c_000769`, `c_000425`, `c_000246`.

Ещё шесть строк имеют искусственно далёкие ID `c_900006` … `c_900011`, но
совпадают с исходными компаниями по названию, городу, адресу, рейтингу, сайту и
телефону. Отличаются ID и оформление кавычек в названии. Например:

- CSV `c_900008` / `АО Флагман Лаб` совпадает с JSON `c_000229` /
  `АО «Флагман Лаб»`;
- CSV `c_900009` / `АО Сокол` совпадает с JSON `c_000656` / `АО «Сокол»`;
- CSV `c_900010` / `Модуль Строй` совпадает с JSON `c_000571` /
  `«Модуль Строй»`.

Эти записи не добавляются повторно благодаря нормализованному бизнес-ключу.

## 2. Повторные строки

В конце CSV повторены три ранее встречавшиеся записи:

- `c_001049`: строки 42 и 204;
- `c_001050`: строки 117 и 205;
- `c_001075`: строки 7 и 206.

Последние две строки файла (207 и 208) полностью пустые.

В исходных JSON также есть 6 полных дублей ID: `c_000224`, `c_000254`,
`c_000263`, `c_000285`, `c_000367`, `c_000453`.

## 3. Некорректные числа

- строка 9, `c_001083`: рейтинг `N/A`;
- строка 14, `c_001010`: рейтинг `4,5` вместо `4.5` — однозначно нормализован;
- строка 61, `c_001116`: `reviews_count = -10`;
- строка 96, `c_001122`: рейтинг `-3`;
- строка 98, `c_001079`: `reviews_count = 45.5`;
- строка 197, `c_001186`: рейтинг `7.2`;
- строка 200, `c_001187`: `reviews_count = "много"`.

Значения вне допустимого диапазона и нецелое число отзывов отклоняются, потому
что безопасного исправления для них нет.

## 4. Повреждённые сайты

- строка 50, `c_001132`: `https://` без домена;
- строка 130, `c_001064`: текст `нет сайта` вместо пустого значения;
- строка 141, `c_001020`: опечатка в схеме `htp://...`.

Строки помещаются в `import_rejections`. Автоматически превращать `htp` в `http`
опасно: импортёр не должен угадывать адрес.

## 5. Сломанная кодировка

Две строки содержат mojibake — UTF-8, ошибочно интерпретированный как другая
кодировка:

- строка 113, `c_001008`: повреждены название и город;
- строка 155, `c_001128`: повреждены название и город.

Обе строки отклонены. Автоматическое перекодирование не применяется, поскольку
оно может необратимо испортить смешанный или уже корректный текст.

## 6. Города и смещение колонок

- `Moscow`, `москва` и `Москва ` обозначают один город; они приведены к `Москва`;
- опечатка `Санкат-Петербург` приведена к `Санкт-Петербург`;
- строка 37 (`c_001015`) структурно сдвинута: в `category` лежит `Пермь`, в
  `city` — адрес, а `address` пуст. Строка отклонена, так как настоящая категория
  отсутствует.

## Как это обнаружено

Импортёр валидирует типы, диапазоны, URL, обязательные поля и признаки сломанной
кодировки до записи в PostgreSQL. Затем значения ID и нормализованные
`name + city + address` сравниваются с уже загруженными компаниями. Все
отклонения сохраняются в `import_rejections`, поэтому результат можно проверить
запросом:

```sql
SELECT source_file, row_number, source_id, reasons, raw_record
FROM import_rejections
ORDER BY id;
```
